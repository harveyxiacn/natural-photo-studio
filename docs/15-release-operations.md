# 发布与运维

## 1. 发布渠道

| 渠道 | 用户 | 更新频率 | 数据/格式保证 |
|---|---|---|---|
| Dev/Nightly | 内部 | 每日 | 可重建项目，禁止生产素材 |
| Alpha | 邀请测试 | 1–2 周 | 迁移测试但可能变更 |
| Beta | 扩大测试 | 2–4 周 | 格式主版本稳定，提供回滚 |
| Stable | 正式用户 | 4–8 周 | 完整兼容和质量门禁 |
| LTS/Enterprise | 企业 | 季度/安全修复 | 固定模型、离线包、延长支持 |

模型、预设和应用可以独立发布，但都必须有版本、签名、灰度和回滚。

## 2. 构建与供应链

- 固定编译器、SDK、依赖和模型哈希；
- Windows/macOS 正式代码签名与公证；
- 生成 SBOM、第三方 NOTICE 和许可证清单；
- 构建产物在隔离 CI 中产生；
- 密钥使用硬件/托管签名，不进入构建日志；
- 更新元数据签名并防回滚；
- Release 产物做恶意软件扫描和可重现性比较；
- 第三方依赖高危漏洞阻断 Stable。
- 引入 Qt 桌面层前冻结许可与链接策略；未经许可证审查不得把静态 Qt 或其插件
  直接纳入公开发行包。

### 2.1 桌面平台与交付物

1.0 的正式桌面目标是 Windows 与 Apple Silicon macOS。C++23 的命令、
文档、成像、颜色和 AI 路由核心共享；Qt 6/QML 桌面层共享主要交互，但文件
对话框、菜单、凭据、无障碍、签名和更新使用平台原生适配。Linux 只作为
核心构建与开发验证环境，不在 1.0 用户支持承诺内。

| 项目 | Windows | macOS |
|---|---|---|
| 应用入口 | `NaturalPhotoStudio.exe` | `Natural Photo Studio.app` |
| 正式分发 | 签名 `.exe` 安装器；评估同时提供 `.msix` | 签名并公证的 `.app`，装入 `.dmg`；企业渠道可提供 `.pkg` |
| 首发架构 | x86-64；Windows on ARM 原生版需单独通过门禁 | Apple Silicon 原生通用目标；不以 Rosetta 作为正式运行前提 |
| GPU 路径 | D3D12/DirectML，按设备路由；CPU 安全降级 | Metal/Core ML，按设备路由；CPU 安全降级 |
| 签名门禁 | Authenticode、可信时间戳、安装/卸载和恶意软件扫描 | Developer ID、Hardened Runtime、Notarization、Stapling 与 Gatekeeper 验证 |
| 系统范围 | 发布时仍受厂商支持的 Windows 版本；精确最低版本在 RC 冻结 | 正式发布版及前一版 macOS；Apple Silicon |

两个平台必须打开同一主版本的 `.npsproj`，并对 CPU 参考渲染、项目迁移、
颜色语义和命令协议运行兼容测试。平台专属 GPU 结果允许在书面误差预算内
存在浮点差异，但不得改变编辑意图或历史。安装包不捆绑未经审核的模型，
模型包使用独立签名清单按平台与硬件下载。

每个 Release 候选都必须在全新系统和覆盖升级两种环境中验证安装、首次
启动、文件关联、更新、回滚和卸载；卸载默认保留用户项目，并明确询问是否
删除缓存与下载模型。签名密钥只存在于受保护的发布环境，公共分支和来自
Fork 的 CI 永远不能访问签名凭据。

## 3. 安装与更新

- 支持全量和差分包；
- 下载断点续传、哈希和签名验证；
- 更新前检查磁盘和运行中导出；
- 应用关闭后原子替换；
- 新版首次启动前保留上一可运行版本；
- 项目迁移在打开项目时独立发生，不因应用安装批量改写所有项目；
- 更新失败自动回到上一版本；
- 离线安装包包含清单和签名验证工具。

## 4. 模型更新

- 模型包与应用分离下载；
- 先验证许可、签名、运行时和设备兼容；
- 下载到隔离目录，验证后原子激活；
- 能力别名支持 canary/stable/pinned；
- 新模型不自动重渲染已冻结项目；
- 磁盘空间不足时列出可删除旧模型；
- 企业策略可只允许审批清单；
- 紧急事故可阻止新任务使用某版本，但旧冻结补丁仍可打开。

## 5. Feature Flag

Flag 用于灰度而不是永久隐藏未完成代码：

- 范围：用户群、平台、GPU、地区和渠道；
- 明确默认值与到期日期；
- 服务不可用时有本地缓存策略；
- 安全关键默认值不能被远程调低；
- Flag 变化写入脱敏诊断；
- 发布稳定后清理旧 Flag。

## 6. 服务指标

即使软件本地优先，也要观察：

- 无崩溃会话率；
- 项目恢复成功率；
- 保存/导出失败率；
- GPU/模型降级率；
- AI 任务失败、取消、立即撤销率；
- P95 启动、预览、保存、导出；
- 云端请求成功、延迟、删除状态和费用；
- 插件崩溃/越权；
- 更新成功/回滚；
- 各模型 QA 失败率。

所有指标采用数据最小化，不上传照片或身份数据。

## 7. 崩溃和恢复

启动检查：

1. 上次是否干净关闭；
2. 项目 WAL 和未完成对象；
3. GPU/插件/模型是否导致连续崩溃；
4. 上次自动保存修订；
5. 磁盘和缓存健康。

恢复界面提供：

- 打开最近有效版本；
- 只读检查；
- 禁用插件/模型的安全模式；
- 复制为恢复项目；
- 查看脱敏原因；
- 不覆盖原项目。

连续两次在相同模块启动崩溃时自动建议安全模式，不形成无限崩溃循环。

## 8. 诊断与支持

应用内诊断：

- 设备/GPU/驱动、应用和模型版本；
- 项目结构摘要，不含名称/路径；
- 最近稳定错误码；
- 性能和资源；
- 签名/依赖状态；
- 可选渲染节点列表。

用户生成支持包前预览清单。局部截图或项目样本必须由用户主动添加，并显示可能包含的人脸/位置风险。

## 9. 备份和项目健康

- 自动保存是项目内恢复，不等于外部备份；
- 提醒用户对重要项目启用系统备份；
- 项目检查器验证数据库、对象哈希、缺失源和模型依赖；
- “优化项目”只清理无引用对象和缓存，先输出预计回收；
- 迁移前保存元数据备份；
- 支持导出便携 `.nps` 和校验报告；
- 不承诺云同步除非单独设计冲突、加密和版本策略。

## 10. 事件响应

| 级别 | 示例 | 目标动作 |
|---|---|---|
| SEV-0 | 原图损坏、未授权上传、签名链攻击 | 立即暂停渠道/模型，启动应急 |
| SEV-1 | 项目损坏、高危插件逃逸 | 当日缓解/回滚和用户通知评估 |
| SEV-2 | 特定 GPU 崩溃、模型显著退化 | 灰度停止、设备降级、修复计划 |
| SEV-3 | 一般缺陷/性能回归 | 正常迭代 |

远程暂停能力只能关闭云 Provider、模型别名或插件版本，不能远程删除用户项目。

## 11. 版本兼容

- Stable 支持打开所有 1.x 旧项目；
- 项目升级前备份，失败可只读；
- 插件 SDK 提供至少一个主版本迁移窗口；
- 模型节点保存冻结结果和版本；
- 导出配方与预设分别版本化；
- 删除兼容路径前提供项目扫描和迁移报告；
- EOL 至少提前一个 Stable 周期通知。

## 12. 发布检查表

### 代码与制品

- 编译、静态分析、测试和 SBOM；
- 签名、公证、哈希和恶意软件扫描；
- 第三方许可与 NOTICE；
- 安装、更新、回滚和卸载；
- 新/旧项目迁移。

### 图像与 AI

- 颜色金图和 CPU/GPU 差分；
- 模型契约、全量评测和盲评；
- 困难样例与已知问题；
- 模型/素材许可；
- 低显存、CPU、离线；
- 生成来源。

### 安全与隐私

- 未解决高危为零；
- 网络端点和云数据流；
- 日志/遥测/诊断扫描；
- 插件/模型/项目签名；
- 权限和高风险确认；
- 隐私文案与删除流程。

### 产品

- P0/P1 缺陷为零；
- 性能预算或批准豁免；
- 无障碍和中文/英文；
- 帮助、错误、恢复和发布说明；
- 支持团队已知问题和回退指引。
