# ADR-0004：所有入口统一为类型化命令

- 状态：Proposed
- 日期：2026-07-25
- 关联：NL-001 至 NL-008、PRO-006、SEC-003

## 背景

按钮、快捷键、自然语言、插件和批处理若直接调用不同内部接口：

- 权限和确认规则会不一致；
- 撤销和审计难以完整；
- 插件或 LLM 可能获得过大能力；
- 同一功能产生不同结果；
- 自动化难以测试。

## 决定

- 所有永久修改通过版本化 `Command Bus`；
- 命令由 Schema 定义类型、目标、参数、约束、风险和隐私；
- 使用 `expectedRevision` 防止过期写入；
- 使用幂等键处理重试；
- 多步任务使用原子批次；
- 预览在临时分支，应用后才成为事务；
- 自然语言只生成注册命令，不能生成脚本或任意调用；
- 插件通过同一协议且受能力令牌约束；
- 结果返回变更、版本、QA、降级和错误；
- 稳定错误码与用户文案分离。

## 结果

正面：

- 所有入口行为一致；
- 可统一撤销、审计、权限和测试；
- 自然语言和插件能力可严格限制；
- CLI/批处理可复用；
- 修订冲突和晚到任务可检测。

代价：

- 每项功能必须先设计 Schema；
- 高频画笔需要“手势流 + 最终命令”的优化边界；
- 协议版本和生成绑定增加工程成本；
- 不能以临时脚本快速绕过系统。

## 特殊情况

画笔移动可作为低延迟临时手势流进入预览缓存，但抬笔后必须生成一个规范命令；崩溃时最多丢失未提交笔划。

只读 UI 状态（面板展开、光标）不进入命令总线；会影响最终像素、项目或外部数据的操作必须进入。

## 被否决方案

### LLM 直接调用引擎/脚本

无法可靠验证目标、权限和参数，也难以撤销。

### 插件直接访问文档对象

会破坏不变量，难以隔离和迁移。

### UI 直接修改节点

看似简单，但会让批处理、语言和插件重复实现事务语义。

## 验证

- UI 与自然语言生成相同命令时结果一致；
- 未注册命令、越界参数、过期修订和越权能力均拒绝；
- 重复幂等请求只提交一次；
- 原子批次中途失败不产生新修订；
- 旧预览晚到不会覆盖新文档；
- 插件和语言执行任意文件/网络/脚本次数为零。
