# 术语与开放问题

## 1. 术语

| 术语 | 定义 |
|---|---|
| Analysis Graph | 分析图片并产生蒙版、深度、关键点等派生资产的图，不修改像素 |
| Edit Graph / DAG | 保存用户意图、节点和依赖的非破坏编辑有向无环图 |
| Render Graph | 针对当前设备、ROI 和质量档编译出的临时执行图 |
| DocumentSnapshot | 某个修订号下不可变的完整文档状态 |
| Transaction | 一组原子文档修改；全成或全不成 |
| Preview Branch | 不进入正式历史的临时候选分支 |
| ROI | Region of Interest，需要读取或重算的区域 |
| Tile / Halo | 分块像素及滤波所需的重叠边界 |
| MaskAsset | 带 Alpha、置信度、来源和人工覆盖的蒙版资产 |
| Matting | 对头发、毛发、薄纱等估计半透明 Alpha |
| Scene-referred | 表示场景光能关系的图像域 |
| Display-referred | 针对显示效果的图像域 |
| View Transform | 从工作空间到观察显示外观的变换 |
| Smart Preview | 用于快速交互、可回到原始源重新渲染的代理图 |
| Frozen Asset | 为长期复现保存的生成或插件像素结果 |
| Capability Alias | 业务引用的稳定模型/功能名，由路由器解析具体版本 |
| Provider | 本地、企业或云端能力实现 |
| EditPlan | 自然语言经解析、校验后的结构化编辑计划 |
| Content-aware Preset | 含规则和语义蒙版的编辑配方，不只是 LUT |
| Identity Preservation | 限制外貌变化并保护人物识别特征的产品策略 |
| Structure-aware Inpainting | 先恢复线、平面、阴影和透视，再融合纹理的移除流程 |
| QA Heatmap | 标示可能伪影或低置信度位置的画布覆盖层 |
| Golden Image | 用于确定性渲染回归的受控参考图 |
| Blind Review | 评审不知道模型/版本信息的主观质量评价 |

## 2. 已采用的工作假设

这些假设使设计可以继续，不等于最终商业决定：

1. 工作名为 Natural Photo Studio；
2. 1.0 聚焦照片，不覆盖完整矢量、视频、3D 和专业排版；
3. Windows 优先完成技术尖峰，1.0 同时支持 Windows 和 Apple Silicon macOS；
4. 桌面原生、项目本地优先；
5. 核心基础编辑不要求云端登录；
6. 云端 AI 默认每个任务询问；
7. 原图只读，工作项目为 `.npsproj`，分享包为 `.nps`；
8. C++23 + Qt/QML 为当前实现候选；
9. 内部使用场景线性宽色域 FP16/FP32，具体默认色域待颜色尖峰；
10. 16GB 为最低内存、32GB 为推荐，4GB/8GB 显存分级；
11. 中文和英文为 1.0 语言；
12. 插件默认 WASM/隔离进程；
13. 用户素材默认不训练模型。

## 3. 编码前必须决定

| ID | 问题 | 当前建议 | 影响 |
|---|---|---|---|
| OQ-001 | 产品最终名称与商标 | 先用工作名，发布前检索 | 品牌、文件关联 |
| OQ-002 | 1.0 精确平台版本 | Windows + Apple Silicon macOS | CI、GPU、支持成本 |
| OQ-003 | 默认工作色域 | 在线性 Rec.2020 与 ACEScg 中实测 | 工程格式、颜色算子 |
| OQ-004 | 首批 GPU 抽象 | D3D12/Metal/Vulkan 或 Dawn 尖峰 | 性能、Qt 互操作 |
| OQ-005 | RAW 解码组合 | LibRaw/RawSpeed 抽象后实测 | 相机覆盖、许可 |
| OQ-006 | PSD 兼容深度 | 1.0 明确支持子集 | 范围、第三方库 |
| OQ-007 | CMYK 是否进 1.0 | 建议软打样，有限转换 | 专业印刷用户 |
| OQ-008 | 云端 Provider | 保持抽象，法务/地区后选择 | 成本、隐私 |
| OQ-009 | 本地模型下载体积 | 核心包 + 按需质量包 | 安装与磁盘 |
| OQ-010 | 项目加密 | 建议 P1/企业，先设计接口 | 密钥和恢复 |
| OQ-011 | 插件市场 | 1.x，1.0 先 SDK/手动安装 | 安全/审核 |
| OQ-012 | 商业模式 | 不让订阅状态破坏离线项目 | 授权、更新 |
| OQ-013 | 团队与时间预算 | 10–14 人、18–24 个月 | 范围和路线 |
| OQ-014 | 评测素材来源 | 先建立许可小集和专业合作 | AI 门禁 |

## 4. 可延后决定

- 在线审片与团队协作；
- Linux 正式支持；
- 云项目同步；
- 插件市场分成；
- 拍摄现场联机；
- 高级矢量和版式；
- 私有企业模型训练；
- 移动端伴侣应用。

这些能力应使用现有项目、命令和 Provider 契约扩展，不应提前侵入 1.0 核心。

## 5. 评审会议建议

设计评审分三场，每场有明确输出：

1. 产品/修图：01–05，冻结 1.0 范围、自然默认和端到端场景；
2. 架构/颜色/AI：06–09 与 ADR，冻结技术尖峰和持久化边界；
3. 安全/质量/交付：10–15，冻结数据、性能、测试、人员和发布门槛。

评审结束不要求所有细节永不变化，但必须把会影响项目格式、权限和用户承诺的事项转成 Accepted ADR。
